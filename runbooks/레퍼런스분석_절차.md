# 런북 — 레퍼런스 영상 분석과 형식 분류

> 요약: 새 레퍼런스 영상을 받았을 때 **무엇을 재고, 어느 형식으로 분류하고, 무엇을 기록하는지**. 형식 4종의 판별 기준·엔진 매핑·선택 기준이 들어 있다. "이 영상 분석해줘 / 어떤 형식으로 만들까" 요청에 연다.

## 1. 먼저 돌릴 것 (재는 건 사람이 하지 않는다)
```bash
python tools/analyze_video.py <영상경로>
```
길이·해상도·fps·오디오 유무, 컷 지점(임계값 2단), 컷 간격 통계, 대표 색, 컨택트시트, **형식 자동 추정**이 나온다.

⚠ 컷이 적은 영상은 임계값 0.25로 **0건**이 나온다. 스크립트는 0.03도 같이 재므로 "변화(0.03)" 줄을 봐야 교체 시점이 보인다.

## 2. 형식 4종

### A. 설명형 — 말이 끌고 간다
사람이 말하고 그래픽이 뒷받침한다. 자막이 매 컷 바뀐다.
- **지표**: 분당 컷 20회 이상, 40~60초, 토킹헤드 있음, 자막 상시
- **쓸 때**: 말로 설명해야 이해되는 것(개념·비교·경험담)
- **엔진**: `layout: split` + `terminal-list`·`icon-flow`·`before-after`·`face-only`
- **실례**: `factsheets/레퍼런스분석_claude스킬5_20260914.md` (56.7초, 컷 30회 = 분당 31.7회)
- **실패 방식**: 그래픽이 말을 그대로 반복하면 지루해진다. 자막과 그래픽은 서로 다른 정보를 담아야 한다.

### B. 서사형 — 문제에서 결과까지 데려간다
훅→문제→해결→시연→차별점→결과→CTA 의 7단. 사기 전 납득이 필요한 제품에 쓴다.
- **지표**: 40초, 장면 7개(각 3~7초), 자막 상시, CTA 1개
- **쓸 때**: 제품·서비스를 처음 보는 사람에게 파는 영상
- **엔진**: `profile: "product-demo-40"` 가 구조를 강제한다 + `statement`·`browser-mock`·`before-after`
- **절차**: `runbooks/제품데모영상_기획절차.md`
- **실패 방식**: 기능을 여러 개 넣으면 아무것도 안 남는다. 기능 하나·결과 하나·CTA 하나.

### C. 시연형 — 화면이 증명한다
요청 → 실행 → 결과를 항목마다 반복한다. 카드 한 장이 유지되고 내용만 바뀐다.
- **지표**: 분당 컷 0.5~5회, 20~40초, 토킹헤드 없음, 자막 1~1.5초마다
- **쓸 때**: "이 도구가 뭘 해주는지"를 화면으로 보여주면 이해되는 것
- **엔진**: `layout: card` + `toggle-list`→`app-intro`→`prompt-run`→`social-cta`
- **실례**: `factsheets/레퍼런스분석_마케팅커넥터5_20261016.md` (32.6초, 컷 1회 — 코드 생성)
  `factsheets/레퍼런스분석_스마트홈녹화형_20261030.md` (53.5초, 컷 0회 — **화면 녹화**, 자막 상단)
- **실패 방식**: 결과 화면에 지어낸 수치를 쓰는 것. `sample: true` 로 "예시" 라벨을 달아야 한다.

### D. 전시형 — 보기만 해도 설득된다
자막도 사람도 내레이션도 없다. 결과물 자체를 크게 보여주고 끝난다.
- **지표**: **컷 0회**, 5~12초, 자막 0개, 루프 전제
- **쓸 때**: 만든 것의 완성도가 그 자체로 설득력 있을 때(UI 킷·템플릿·포트폴리오)
- **엔진**: **미구현** — `showcase` 레이아웃 + `code-window` + `screen-cycle` 필요 (`KNOWN-GAPS.md`)
- **실례**: `factsheets/레퍼런스분석_UI킷쇼케이스_20261030.md` (6.1초, 컷 0회 — 스크린샷)
  `factsheets/레퍼런스분석_웹사이트스크롤_20261030.md` (46.0초, 컷 0회 — **데스크톱 녹화**, 인트로만 자막)
- **길이는 소재가 정한다**: 스크린샷이면 5~12초, 스크롤 녹화면 40초가 넘어도 된다(사이트가 서사를 갖는다)
- **실패 방식**: 설명을 넣고 싶어지는 것. 넣는 순간 A·C 형식의 열화판이 된다.

## 2.5 소재 축 — 형식만으로는 안 갈린다 (2026-10-30 추가)
형식(무엇을 보여주나)과 **소재**(무엇으로 만드나)는 별개다. 같은 시연형이라도 만드는 방법이 완전히 다르다.

| 소재 | 만드는 법 | 바꿀 때 | 실례 |
|---|---|---|---|
| **코드 생성** | spec 작성 → 렌더 | 텍스트만 고치면 됨 | 레퍼런스 2 (카드형) |
| **화면 녹화** | 녹화 → 트림 → 자막 얹기 | **다시 찍어야 함** | 레퍼런스 4 (스마트홈) |
| **실사 촬영** | 촬영 → 편집 | 다시 찍어야 함 | 레퍼런스 4 인트로(조명 장면) |

**형식 × 소재는 자유롭게 조합된다.** 지금까지 본 조합:

| | 코드 생성 | 화면 녹화 | 스크린샷 |
|---|---|---|---|
| C 시연형 | 레퍼런스 2 (커넥터) | 레퍼런스 4 (스마트홈, 폰) | — |
| D 전시형 | — | **레퍼런스 5 (todah.dev, 데스크톱)** | 레퍼런스 3 (UI 킷) |

레퍼런스 4 와 5 는 **둘 다 컷 0회 + 화면 녹화**인데 유형이 갈린다. **자막이 있으면 C, 없으면 D** 다.

**판단 기준**: 제품 UI 가 **이미 완성돼 있으면 녹화**가 빠르고 정확하다.
아직 없거나(기획 단계), 실제로는 그렇게 안 보이거나(연출이 필요), 자주 바뀌면 **코드 생성**이 맞다.
녹화는 영상 품질의 상한이 녹화 품질에 묶인다는 비용을 치른다.

## 3. 자동 판별 기준 (tools/analyze_video.py 와 같은 값)
| 조건 | 추정 |
|---|---|
| 컷 0회 + 12초 이하 | **전시형(D)** |
| 컷 0회 + 12초 초과 | **녹화·유지형** — 화면이 연속으로 흐른다. 자막 유무로 C(자막 있음) / D(없음) 을 가른다 |
| 분당 컷 20회 이상 | **설명형(A)** |
| 분당 컷 0.5회 이상 | **시연형(C) 또는 서사형(B)** — 아래로 더 가른다 |

**C와 B를 가르는 것**: 구조다. 항목이 **반복**되면(도구 1→2→3) C, 문제→해결→결과로 **진행**하면 B.

⚠ **분류기의 한계**: 스크립트는 컷만 센다. **자막 유무와 소재는 못 본다.**
컷 0회가 나오면 반드시 컨택트시트를 눈으로 확인해라 — 레퍼런스 4(53초·컷 0회)가 전시형으로 잘못 추정됐고,
실제로는 녹화형이었다. 숫자는 후보를 좁혀줄 뿐 결론이 아니다.

## 4. 분류 후 재는 것 (factsheets 에 기록할 항목)
1. **레이아웃 좌표** — 카드/밴드의 상·하단, 좌우 여백, 자막 Y. 세로 한 줄의 밝기 프로파일로 경계를 찾는다
   ```bash
   ffmpeg -ss <초> -i in.mp4 -frames:v 1 -vf "crop=2:<높이>:<x>:0,scale=1:<높이>" -f rawvideo -pix_fmt gray -
   ```
2. **색** — 배경·카드·강조·보조. 스크립트가 3곳을 자동으로 뽑고, 나머지는 `crop=...,scale=1:1` 로 찍는다
3. **타이포 크기** — 자막·제목·라벨을 원본 해상도 기준으로 재고 1080 환산값을 같이 적는다
4. **모티프 목록** — 움직이는 것을 전부 세고, 각각이 엔진의 어느 씬에 대응하는지 표로
5. **전개 구조** — 구간별 초 단위 배분
6. **엔진에 없는 것** — 재현하려면 뭐가 필요한지. 이게 KNOWN-GAPS 로 간다

## 5. 형식 고르는 기준 (새 영상을 만들 때)
한 줄로 답해 본다 — **"왜 이걸 봐야 하죠?"**
- 설명해야 이해된다 → **A 설명형**
- 지금 겪는 문제가 있다 → **B 서사형**
- 뭘 해주는지 보면 안다 → **C 시연형**
- 보면 갖고 싶다 → **D 전시형**

길이는 형식이 정한다. 40초짜리를 6초로 줄이는 게 아니라, **형식을 바꾸면 길이가 따라온다.**

## 6. 하지 말 것
- 형식을 섞지 마라. 전시형에 자막을 넣거나 설명형에서 사람을 빼면 둘 다 안 된다.
- 레퍼런스의 **수치를 추정하지 마라.** 스크립트로 재고 그 값을 적는다.
- 분석만 하고 끝내지 마라. 숫자로 적을 수 있는 건 `engine/` 게이트로 내린다 (`CLAUDE.md` §3).
