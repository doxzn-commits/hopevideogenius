# 런북 — 새 씬 타입 추가하기

> 요약: 레퍼런스에서 본 모션 모티프를 엔진 씬 타입으로 승격하는 절차(4곳 수정). "이런 장면도 만들고 싶다"는 요청이 오면 연다.

## 언제 코드로 내리나
다음 중 하나라도 해당하면 문서가 아니라 **코드**다 (CLAUDE.md §3 승격 규칙).
- 레이어 순서·임계값·프레임 수처럼 숫자로 적을 수 있는 파라미터가 있다
- "이렇게 하면 실패한다"가 자동 판정 가능하다
- 다른 소재로 갈아 끼우면 재사용된다

## 고칠 곳 4개 (순서대로)
1. **`engine/src/spec/schema.ts`** — `xxxProps` zod 스키마 정의 + `sceneSchema` 의 union 에 추가
2. **`engine/src/spec/timelines.ts`** — `xxxTimeline(props)` 로 내부 타이밍을 계산하고 `sceneEnd()` switch 에 추가
   → 컴포넌트와 게이트가 **같은 함수**를 쓰게 한다. 이게 "애니메이션 잘림"을 자동으로 막는 장치다.
3. **`engine/src/scenes/Xxx.tsx`** — 컴포넌트. 타이밍 값은 전부 2번에서 가져온다(컴포넌트에 숫자를 새로 박지 마라)
4. **`engine/src/scenes/registry.ts`** — 타입 이름 → 컴포넌트 매핑

필요하면 5. `engine/src/spec/gate.ts` 에 타입 전용 규칙(개수 상한 등)을 `RULES` 상수로 추가한다.

## 규칙
- 씬 컴포넌트는 팔레트(`p`)와 spec props 만 받는다. 색·좌표를 직접 하드코딩하지 않는다.
- 좌표는 `src/spec/layout.ts`, 색은 `src/theme.ts` 의 `PALETTES` 가 원천이다.
- 애니메이션은 `useCurrentFrame()` + `interpolate()` 로만. CSS transition/animation 은 렌더에 안 나온다.
- `transform` 문자열 대신 `scale` / `translate` / `rotate` 개별 속성을 쓴다(Studio 에서 편집 가능).

## 확인
```bash
cd engine
npm run lint:spec          # 게이트 + 레이아웃 불변식
npx tsc                    # 레지스트리 타입 매칭 확인
npx remotion still <id> --frame=<프레임> --scale=0.5 out/x.png
```
씬을 추가했으면 데모 spec(`specs/demo-repo-rules.json`)이나 새 spec 에 한 씬 넣어 실제로 렌더해 본다. 렌더 안 해보고 끝내지 마라.
