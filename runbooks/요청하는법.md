# 런북 — AI에게 영상을 요청하는 법

> 요약: 이 레포를 clone 한 AI에게 **무엇을 어떻게 요청하면 영상이 나오는지**. 복사해서 쓰는 요청문 3종과 필요한 정보 목록. "어떻게 시켜야 해 / 뭐라고 요청해 / 새 컴퓨터에서 시작" 같은 질문에 연다.

## 0. 새 컴퓨터에서 처음이라면
```bash
git clone https://github.com/doxzn-commits/hopevideogenius.git
cd hopevideogenius/engine && npm ci
```
필요한 것: **Node 24+**, git. (ffmpeg 은 레퍼런스 영상을 분석할 때만 필요)
AI에게는 첫 메시지에 이렇게 말한다: **"이 레포의 `00_부팅.md` 와 `INDEX.md` 를 먼저 읽고 시작해."**

## 1. 지금 만들 수 있는 것 / 없는 것

| 형태 | 상태 | 요청 방법 |
|---|---|---|
| **A. 토킹헤드 + 모션그래픽** (사람 영상 + 상단 그래픽 + 큰 자막) | ✅ 가능 | §2-A |
| **B. 제품 데모 40초** (7단 구조, 브라우저 목업·커서·클릭) | ✅ 가능 | §2-B |
| **C. 카드형 도구 소개** (카드 1장 유지, 요청문→실행→결과) | ✅ 가능 | §2-C |
| **D. 게시물 본문(캡션)** | ✅ 가능 | §2-D |

C 의 인트로(토글 리스트)와 CTA(팔로우→댓글→DM) 전용 씬은 아직 없다 → `KNOWN-GAPS.md`

## 2. 복사해서 쓰는 요청문

### A. 토킹헤드 + 모션그래픽 영상
```
이 레포의 00_부팅.md 와 INDEX.md 를 먼저 읽어.
runbooks/정보전달영상_제작절차.md 대로 영상 한 편을 만들어줘.

[주제] ○○
[대본] (내가 말할 문장들을 그대로 붙여넣기 — 또는 "대본도 네가 써줘")
[사람 영상] engine/public/talking-head.mp4 (없으면 "없음" 이라고 쓰면 자리표시로 렌더된다)
[길이] 40초 내외
[레퍼런스] factsheets/레퍼런스분석_claude스킬5_20260914.md 의 스타일로

spec 을 만들고 npm run lint:spec 를 통과시킨 뒤, 스틸 몇 장을 렌더해서 보여줘.
```

### B. 제품 데모 40초
```
이 레포의 00_부팅.md 와 INDEX.md 를 먼저 읽어.
runbooks/제품데모영상_기획절차.md 대로 제품 데모 영상을 만들어줘.
engine/specs/template-product-demo-40.json 을 복사해서 시작하면 된다.

- 제품명:
- 주요 고객:
- 이번에 보여줄 핵심 기능 하나:
- 사용 전 방식 / 사용 후 결과:
- CTA:

없는 기능은 절대 만들어내지 말고, 모르는 건 최대 5개까지만 물어봐.
lint:spec 통과시키고 40초 mp4 까지 렌더해줘.
```
**이 5개만 주면 된다.** 나머지(길이·비율·팔레트·장면 수)는 프로필이 정한다.

### C. 카드형 도구 소개 (카드 1장 유지, 내용만 교체)
```
이 레포의 00_부팅.md 와 INDEX.md 를 먼저 읽어.
factsheets/레퍼런스분석_마케팅커넥터5_20261016.md 의 형태로 영상을 만들어줘.
engine/specs/template-card-tools.json 을 복사해서 시작하면 된다.

[소개할 도구들] 이름 · 아이콘 글자 · 그걸로 하는 일
  예) Bright Data · B · 릴스 조사
[도구마다 요청문] AI에게 실제로 치는 문장 (46자 이내)
[도구마다 결과 화면] thumbs(썸네일 순위) / table(표+토글) / funnel(이탈 막대) / upload(업로드 예약) 중 하나
[CTA] 댓글 키워드 한 단어

결과 수치는 지어내지 말고 sample: true 로 "예시" 라벨을 붙여.
lint:spec 통과시키고 스틸로 보여줘.
```

### D. 게시물 본문
```
runbooks/소셜본문_작성절차.md 대로 이 영상의 본문을 써줘.
형태는 factsheets/소셜본문_예시_마케팅커넥터5_20261016.md 를 따르고,
영상 spec 은 engine/specs/○○.json 이야.
```

## 3. 요청할 때 꼭 넣을 것 / 넣지 말 것

**넣을 것**
- 읽을 문서 지정 (`00_부팅.md` → `INDEX.md`). 이게 없으면 AI 가 레포를 안 읽고 자기 방식대로 만든다.
- 실제 내용(대본·제품 정보). 없으면 AI 가 지어낸다.
- 완료 기준: "lint:spec 통과", "스틸 렌더해서 보여줘", "mp4 까지".

**넣지 말 것**
- "알아서 예쁘게" — 수치가 없으면 재현이 안 된다. 스타일은 factsheets 문서를 가리켜라.
- 길이·폰트·색 같은 기본값 재지정. 이미 엔진·게이트가 들고 있다.
- "새 폴더에 새로 만들어줘" — 지식이 레포 밖으로 샌다. 항상 이 레포 안에서 작업시킨다.

## 4. AI 가 이렇게 하면 잘못 가고 있는 것
- 레포 문서를 안 읽고 Remotion 프로젝트를 새로 만들려고 한다 → `00_부팅.md` 를 읽으라고 다시 말한다.
- `npm run lint:spec` 없이 렌더부터 한다 → 게이트를 먼저 통과시키라고 한다.
- 없는 기능을 "구현했다"고 말한다 → `engine/src/scenes/registry.ts` 의 목록을 확인시킨다.
- 작업이 끝났는데 커밋·push 를 안 한다 → `CLAUDE.md` §3 의 정리 규칙을 적용시킨다.
- 제품에 없는 기능을 영상에 넣는다 → 기획 절차의 "발명 금지" 규칙 위반이다.

## 5. 끝났을 때 받아야 할 것
1. `engine/specs/<이름>.json` (spec)
2. `npm run lint:spec` 통과 로그
3. 스틸 몇 장 또는 `out/<이름>.mp4`
4. 새로 알아낸 수치·기법이 있으면 **코드로 내려간 흔적** + `labs/주제_YYYYMMDD.md`
5. 커밋 + **push**
