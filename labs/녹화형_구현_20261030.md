# 녹화형 구현 — screen-record 씬과 자막 상단 배치 (2026-10-30)

> 요약: 실제 화면 녹화를 폰 목업에 넣는 씬과 자막 상단 배치를 엔진에 내린 기록. 게이트에 넣은 `node:fs` 가 렌더 번들을 깨뜨린 실수와 그 경계. "녹화 파일이 왜 게이트에서 검사되나", "자막이 왜 위로 갈 수 있나"에 연다.

## 결론
1. **게이트는 브라우저에서도 돈다.** `gate.ts` 에 `node:fs` 를 쓰면 Studio·렌더 번들이 통째로 깨진다.
   파일 존재 검사 같은 **Node 전용 검사는 `scripts/lint-spec.ts` 에만** 둔다.
2. **자막 위치는 여전히 레이아웃이 정한다.** 씬이 직접 정하게 열지 않았다.
   대신 `phone` 레이아웃의 captionY 를 322(상단)로 두고, 겹침 불변식을 "위/아래 무관"으로 일반화했다.
3. 녹화 파일이 없으면 **렌더가 검은 화면으로 조용히 나간다.** 그래서 게이트에서 오류로 막는다.
   구성만 먼저 잡고 싶을 때는 `src: null` 로 자리표시 프레임을 쓴다(경고만).

## 구조
| 조각 | 위치 | 역할 |
|---|---|---|
| `layout: "phone"` | `spec/layout.ts` `PHONE` | 폰 목업 좌표(555×1013, top 427, r56, bezel 12) + **captionY 322(상단)** |
| `screen-record` | `scenes/ScreenRecord.tsx` | 폰 프레임 + `<Video>` 임베드(`trimBefore`·`fit`) 또는 자리표시 |
| `paper` 팔레트 | `theme.ts` | 거의 순백 `#FDFFFF` + 파란 강조 `#3B5BFE` |
| 파일 존재 검사 | `scripts/lint-spec.ts` | `public/<src>` 없으면 오류 |

게이트 규칙: `screen-record` ↔ `layout: phone` 짝 강제(양방향), `src: null` 은 경고, 파일 없으면 오류.

## 겪은 것

### 1. 게이트에 `node:fs` 를 넣었더니 렌더가 통째로 깨졌다
```
Module build failed: Reading from "node:fs" is not handled by plugins (Unhandled scheme)
```
`gate.ts` 는 `specs.ts` 가 import 하고, 그걸 Studio·렌더 번들러가 읽는다. `try/catch` 로 감싸도 **번들러는 정적으로 본다**.
→ 파일 검사를 `scripts/lint-spec.ts`(Node 전용)로 옮겼다. 게이트는 순수하게 유지한다.
   `spec/layout.ts` 를 remotion 비의존으로 뺐던 것과 **같은 경계**다: 게이트가 닿는 코드는 환경 의존이 없어야 한다.

### 2. 자막 겹침 불변식이 "자막은 그래픽 아래"를 전제하고 있었다
`graphic.bottom > captionY - HALF` 로 판정하고 있어서, 자막이 **위**에 있는 phone 레이아웃이 항상 실패했다.
→ 두 구간이 겹치는지(`capTop < graphic.bottom && capBottom > graphic.top`)로 일반화했다. 위든 아래든 같은 규칙이 된다.

### 3. 녹화 파일 경로는 `public/` 기준이다
`staticFile("screens/x.mp4")` → `engine/public/screens/x.mp4`. mp4 는 `.gitignore` 에 막혀 **커밋되지 않는다**(의도된 것).
다른 컴퓨터에서 같은 spec 을 렌더하려면 녹화 파일을 따로 받아야 한다 — 이건 녹화형의 구조적 비용이다.

## 검증
- 실제 mp4(`public/screens/sample.mp4`)로 렌더 → 폰 안에서 재생, 상단 자막·파란 강조 정상
- 없는 경로(`screens/nope.mp4`) → 게이트 오류 1개로 막힘 ✓
- `src: null` → 자리표시 프레임 + 경고 ✓
- tsc·게이트 통과, 스틸 3장 확인
