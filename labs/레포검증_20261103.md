# 레포 검증 — "문서만 보고 새 영상을 만들 수 있나" (2026-11-03)

> 요약: 레포를 처음 여는 AI에게 가상 요청("사람인 알바 데모")을 주고 문서만으로 계획을 세우게 한 검증 결과와 조치. 문서 모순 7건·구멍 4건이 나왔다.

## 결론
1. **판단은 전부 성공했다.** 유형(B 서사형)·길이(30초)·프로필(`product-demo-30`)·7장면 구성·물어볼 것 5개를
   문서만으로 정확히 골랐다. 라우터와 색인은 작동한다.
2. **문제는 전부 "낡은 문서"였다.** 기능을 추가하고 문서 한 곳만 고치면, 나머지 문서가 과거를 말한다.
3. **게이트는 또 제 역할을 했다.** 새로 만든 30초 템플릿의 강조어 오류(`hl` 이 text 에 없음)를 바로 잡았다.

## 나온 것과 조치

### 문서끼리 어긋난 것 (7건)
| 어긋남 | 조치 |
|---|---|
| 기획절차 §2·§4 는 30초인데 §9 실행 블록은 40초 템플릿을 복사하라고 함 | §9 를 30초 템플릿으로 |
| 요청하는법 §1 표는 "30초", §2-B 제목은 "40초" | 제목·본문 통일 |
| 레퍼런스분석 §2-B 가 아직 "40초, 각 3~7초, product-demo-40" | 30초 기본으로 |
| KNOWN-GAPS 에 "브라우저 목업·폰 목업 없음" 이 남음 (둘 다 구현됨) | 삭제 |
| 레퍼런스분석 §2-D 가 전시형을 "미구현" 이라 함 | 구현 내용으로 교체 |
| "형식을 섞지 마라" vs "유형은 섞인다" 가 충돌 | **"형식은 섞지 말고 씬 타입은 섞어라, 고정되는 건 role 순서"** 로 명시 |
| 미리보기 명령이 `npx remotion studio --no-open` / `npm run studio` 두 가지 | `npm run studio` 로 통일 |

### 구멍 (4건)
- **30초 템플릿이 없었다** → 기본이 30초인데 시작 파일은 고객 사례(carfia)뿐이라 문구 오염 위험.
  `template-product-demo-30.json` 신설(○○ 자리표시).
- **지도 씬이 없다** → KNOWN-GAPS "없는 씬 타입" 에 추가. 지금은 `icon-flow` 로 대신한다.
- **글자 수 상한이 문서에 없었다** → 코드에서 역산되는 값이라 문서에 적으면 또 어긋난다.
  → **`npm run lint:spec` 이 매번 현재 값을 찍게 했다**(자막 19자·statement 15자·name 14자·prompt 46자).
- **앱 제품인데 녹화가 없을 때의 선택지** → 기획절차에 "녹화 없는 앱 데모는 browser-mock 을 앱 화면처럼 쓴다" 명시.

### 코드 버그
- 프로필 오류 메시지가 초를 **하드코딩**("3~7초")해서 30초 프로필에서도 3~7초라고 찍혔다 → 프로필 값에서 계산.

## 교훈
**문서는 코드보다 빨리 낡는다.** 기능 하나를 추가하면 그 기능을 언급하는 문서가 평균 3~4곳 있고,
그중 한 곳만 고치면 나머지가 다음 사람을 틀린 길로 보낸다.
→ 숫자·목록처럼 **코드에서 뽑을 수 있는 것은 문서에 적지 말고 도구가 찍게 한다**(글자 수 상한이 그 예).
→ 기능을 추가할 때 `grep` 으로 그 기능을 언급하는 문서를 **전부** 찾아 같이 고친다.
