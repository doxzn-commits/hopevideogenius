# 카피아 데모 40초 제작 (2026-10-30)

> 요약: 첫 실제 제품 영상. 서사형 7단 뼈대에 시연형 씬(browser-mock·icon-flow·prompt-run)을 섞어 짠 기록과, 그 과정에서 코드로 내린 자막 규칙.

## 결론
1. **유형은 섞인다.** `profile: "product-demo-40"` 은 **장면 수·길이·역할 순서만** 강제하고 씬 타입은 자유다.
   그래서 서사형 뼈대(hook→…→cta) 안에 카드형 `prompt-run`, 시연형 `browser-mock`·`icon-flow` 를 그대로 끼웠다.
2. **팔레트로 장을 나눴다.** 문제 구간은 navy(무겁게), 해결·시연은 ivory(밝게), 결과·CTA 는 pastel(따뜻하게).
3. **수치를 쓰지 않았다.** 절감률·시간은 확인된 값이 없어 막대 라벨을 "발품 / 한 번" 같은 말로 뒀고,
   견적 표에는 `sample: true` 로 "예시" 라벨을 달았다. 실제 데이터가 생기면 그때 숫자를 넣는다.

## 코드로 내린 것
**flat 팔레트(단색 배경)에서는 자막이 plain 스타일로 바뀐다.**
아이보리 배경 위에 흰 글씨 + 검은 외곽선 + 노란 강조가 올라가 겉돌았다.
외곽선과 노란 강조는 **사진·그래픽 위에서** 글자를 띄우려고 쓰는 장치인데, 단색 배경에는 띄울 이유가 없다.
→ `SpecVideo` 에서 `PALETTES[palette].flat` 이면 자막을 plain + 팔레트 accent 로 그린다.
   (card·stack·phone 레이아웃에 걸려 있던 조건에 "flat 팔레트" 를 더한 것)

## 겪은 것
- **강조는 한 단어만.** `hl: "줄어듭니다"` 처럼 문장 전체를 강조하니 강조가 사라졌다 → `hl: "줄어"`.
  (본문 런북에도 같은 규칙이 있다 — 영상 자막에도 똑같이 적용된다)
- 역할(`role`)과 씬 타입을 분리해 둔 설계가 여기서 값을 했다. "문제" 역할에 브라우저 목업을 쓰는 게 자연스러웠다.

## 남은 것
- 실제 견적 데이터가 생기면 표의 `예시` 라벨을 떼고 숫자를 넣는다
- 차종·지역을 바꾼 변형본은 spec 복사 후 요청문·칩·자막만 고치면 된다
- 본문(캡션) 초안: `engine/specs/carfia-40.본문.md`

## 2차 — 피드백 반영 (완성도 60% 지적)
받은 지적 세 가지와 조치:

### 1. "하단부에 층이 나뉘어 있다" — 사람 자리였다
`full-graphic` 의 그래픽 박스(200~1010)는 **아래쪽을 비워 두는데 그게 원래 토킹헤드 자리**다.
사람을 안 쓰니 그 공간이 그냥 빈 채로 남아 화면이 위로 쏠렸다.
→ `resolveLayout()` 신설: `talkingHead: null` 이면 박스를 **240~1290**, 자막을 **1460** 으로 내린다.
→ 거기에 그래픽을 **1.12배** 키운다(폭 960×1.12=1075 로 1080 안에 겨우 들어간다).
**교훈: 레이아웃의 빈 공간은 대개 "무언가를 위해 비워둔 자리"다. 그 무언가를 안 쓰면 공간을 돌려받아야 한다.**

### 2. "후킹 요소가 없다" — 훅이 정지된 글자였다
글자 두 줄 페이드로 4초를 썼다. 첫 3초에 **움직임이 없으면** 넘긴다.
→ 훅을 `terminal-list` 로 바꿔 **딜러별 견적 막대가 차례로 차오르게** 했다.
   "같은 차인데 / 딜러마다 가격이 달라요" — 문제를 글이 아니라 화면으로 보여준다.

### 3. "속도감이 느리다" — 40초가 내용보다 길었다
같은 내용을 40초에 담으니 장면당 5~7초, 자막 교체가 2.3초꼴이었다.
→ **`product-demo-30` 프로필 신설**(900프레임, 7장면, 각 2~6초)하고 30초로 압축.
→ 자막 교체를 **1.2~1.6초**로, 커서 클릭 간격을 34프레임 → 22프레임으로.

**교훈: 속도감은 총 길이를 줄여서 얻는 게 아니라 초당 사건 수를 늘려서 얻는다.**
다만 총 길이가 길면 사건 수를 늘려도 늘어진다 — 둘 다 손봐야 한다.
