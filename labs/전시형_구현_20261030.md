# 전시형 구현 — showcase 레이아웃과 screen-cycle 씬 (2026-10-30)

> 요약: 자막 없는 쇼케이스 형식을 엔진에 내린 기록과, 실측 좌표를 "대충 쌓아서" 어긋났던 실수. "전시형에 왜 자막을 못 넣나", "코드 창 줄 높이가 왜 이 값이야"에 연다.

## 결론
1. **전시형은 자막을 넣으면 게이트가 막는다.** 설명을 넣는 순간 설명형·시연형의 열화판이 되기 때문이다.
   이건 취향이 아니라 레퍼런스 분석의 결론(`레퍼런스분석_UI킷쇼케이스` §2-D)을 코드로 내린 것이다.
2. **좌표는 쌓지 말고 실측값에 각각 맞춘다.** 타이틀 2행을 한 블록으로 쌓았더니 둘째 줄이 UI 밴드에 가렸다.
3. **코드 창은 읽으라고 넣는 게 아니다.** 그래서 내용이 멈춰 있어도 되고, 신택스 색칠도 정규식 한 번이면 충분하다.
4. UI 밴드는 **좌우를 일부러 자른다**(전체폭 1080, `overflow: hidden`). 작게 줄여 전부 보여주면 디테일이 죽는다.

## 구조
| 조각 | 위치 | 역할 |
|---|---|---|
| `layout: "showcase"` | `spec/layout.ts` `SHOWCASE` | 타이틀 537/615, 밴드 665~1255(전체폭), 코드 창 117~965 / 1400~1767 |
| `screen-cycle` | `scenes/ScreenCycle.tsx` | 화면을 같은 길이로 나눠 교체, 스켈레톤 → 콘텐츠, 마무리 스윕 |
| `CodeWindow` | `components/CodeWindow.tsx` | 정규식 토크나이저 + 트래픽 라이트 + 언어 라벨 |
| `ink` 팔레트 | `theme.ts` | 검정 `#020002` + 주황 `#F06036` |

SpecVideo 에 분기를 하나 더 뒀다: `showcase` 는 씬이 **화면 전체를 직접 그린다**(카드형은 틀을 밖에서 그리고, 전시형은 전부 안에서 그린다).

## 게이트에 내린 규칙
- `layout: showcase` ↔ `screen-cycle` 짝 강제(양방향)
- **자막이 하나라도 있으면 오류** — "설명이 필요하면 layout 을 바꿔라"
- 화면당 최소 24프레임(0.8초). 레퍼런스 최단 샷 0.4초 + 여유
- 스크린샷 경로가 없으면 오류, `src: null` 이면 경고(스켈레톤으로 렌더)

## 겪은 것

### 1. 타이틀 둘째 줄이 UI 밴드에 가렸다
`title1Y`(537) 에서 시작해 두 줄을 `marginTop` 으로 쌓았더니 둘째 줄이 660 근처로 밀려 밴드(665)와 겹쳤다.
실측값은 **1행 중심 537, 2행 중심 615** 로 따로 있었는데 그걸 안 쓰고 흐름에 맡긴 게 원인이다.
→ 블록 상단을 `537 - 84/2` 로 잡고 두 줄에 각각 고정 높이(84/70)를 줬다. 밴드까지 15px 여유가 남는다.

### 2. 코드가 창 밖으로 넘쳤다
줄 높이를 1.65 로 잡아 13줄이 403px 가 됐는데 창은 367px 였다.
레퍼런스를 다시 보면 **367px 안에 14줄**이 들어간다 → 헤더 50 을 빼고 줄당 약 22px.
→ `fontSize: 17 / lineHeight: 1.32` 로 맞췄다. **레이아웃 수치를 정할 때 "몇 개가 들어가는지"까지 같이 재야 한다.**

### 3. 신택스 하이라이트에 라이브러리를 쓰지 않았다
Prism·highlight.js 를 넣으면 번들이 커지고 Remotion 렌더에 부담이 된다.
코드 창은 어차피 **읽히지 않는 장식**이라 정규식 한 번(문자열 → 주석 → 태그 → 숫자 → 키워드)으로 충분하다.

## 검증
`template-showcase.json`(1씬 6.7초, 화면 4개)으로 게이트·tsc 통과, 스틸 3장 + mp4 렌더 확인.
스크린샷이 없어 스켈레톤 상태로 렌더되는데, 이건 레퍼런스의 로딩 연출과 같은 모습이라 그대로 템플릿으로 쓸 수 있다.

## 남은 것

- UI 밴드 3D 틸트 마무리(레퍼런스 마지막 0.5초)

## 3차 — 밴드에 영상 넣기 (같은 날, 레퍼런스 5 분석 후)
`screens[].src` 가 mp4·webm·mov 면 `<Video>`, 아니면 `<Img>` 로 분기한다. 확장자 판정 정규식(`VIDEO_EXT`)은
**게이트와 씬이 같은 상수를 공유**한다 — 두 곳이 갈리면 렌더와 검사가 어긋난다.

### 규칙 충돌을 하나 찾았다
영상을 넣자마자 **"씬 280f > 최대 240f"** 로 막혔다. `sceneMaxFrames`(8초)는
"한 화면이 길면 정보가 정체된다"는 설명형·시연형 논리에서 나온 값인데,
**영상이 든 씬에는 그 논리가 적용되지 않는다.** 소재 자체가 시간을 끌고 가기 때문이다.
실제로 레퍼런스 5 는 46초 한 컷, 레퍼런스 4 는 53초 한 컷이다.

→ `mediaSceneMaxFrames`(60초)를 따로 두고, 영상을 품은 씬(`screen-record`,
영상이 있는 `screen-cycle`)만 그 상한을 쓰게 했다.

**교훈: 규칙은 그 규칙이 나온 형식 안에서만 참이다.** 새 형식을 넣을 때 기존 상수가 막으면,
상수를 늘리기 전에 "그 값이 왜 그 값이었는지" 부터 본다. 여기서는 근거가 다른 형식의 것이었다.

추가 규칙: 영상 화면은 **2초 이상** 머물러야 한다(`videoScreenMinFrames: 60`). 0.8초짜리 영상은 움직임이 안 읽힌다.
