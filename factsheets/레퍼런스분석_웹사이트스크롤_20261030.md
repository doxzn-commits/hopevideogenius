# 레퍼런스 분석 — "todah.dev" 웹사이트 스크롤 (2026-10-30)

> 요약: 인트로 2초만 자막이고 나머지 44초는 **데스크톱 웹사이트를 스크롤하는 녹화**가 전부인 46초 영상. 전시형인데 소재가 녹화다. 포트폴리오·웹사이트를 보여주는 영상을 만들 때 연다.

## 결론 (먼저 읽을 것)
1. **유형은 D 전시형, 소재는 데스크톱 화면 녹화다.** 분류의 "형식 × 소재" 표에서 새로 채워진 칸이다.
   (레퍼런스 3 전시형은 소재가 스크린샷이었다)
2. **자막이 인트로에만 있다.** 0~2초 타이틀 3줄 이후 44초 동안 자막이 0개다.
   분류기가 "컷 0회 + 긴 영상 → 자막 유무로 C/D 를 가른다"고 했는데, 이 영상이 그 판정의 실제 사례다.
   같은 컷 0회여도 레퍼런스 4(스마트홈)는 자막이 2~4초마다 있어 **C 시연형**, 이건 없어서 **D 전시형**이다.
3. **설명을 사이트가 대신한다.** 사이트 자체에 큰 카피("귀찮으니까, 만든다", "한 번 만들어 두면,")가 있어서
   영상이 자막을 얹을 필요가 없다. **보여줄 대상이 이미 말을 하고 있으면 자막은 중복이다.**
4. 주소창(`todah.dev`)을 노출한다. 전시형 레퍼런스의 코드 창과 같은 역할 — **"진짜 돌아가는 것"이라는 증거물**이다.
5. 46초는 전시형치곤 길다. 사이트 자체가 스크롤 서사를 갖고 있으면 길어도 된다.

## 2. 레이아웃 (720 기준 → 1080 환산 ×1.5, 근사값)
### 인트로
| 요소 | 720 | 1080 |
|---|---|---|
| 타이틀 3줄 | y 165~400 | 247~600 |
| 강조 박스("비밀") | 파란 면 + 흰 글자, 라운드 12 | 라운드 18 |
| 노트북 목업 | x 85~700 / y 555~950 | x 127~1050 / y 833~1425 |
| "⏸ 재생" pill | 노트북 상단 걸침, 중앙 | — |

노트북은 **살짝 기울어진 3D 목업**이다(원근 약 6~8°). 평평한 사각형보다 "화면"이라는 인상이 강해진다.

전시형 레퍼런스(UI 킷)와 **같은 구조**다: 전체폭 밴드 + 위아래 여백. 다른 건 밴드 안이 정지 이미지가 아니라 **영상**이라는 것.

## 3. 색
| 이름 | 값 | 쓰임 |
|---|---|---|
| 배경 | `#FDFFFF` | 프레임 전체(밴드 위아래) |
| 강조 | 파랑 `#2B4BF5` 계열 | 인트로 "비밀" 박스, 사이트 포인트 색 |
| 사이트 | 다크 `#0A0A0A` ↔ 아이보리 `#ECEDE4` | 섹션마다 바뀜 |

프레임이 쓰는 색은 **흰색 + 파랑 둘뿐**이다. 나머지는 전부 녹화된 사이트의 색이다.

## 4. 인트로 2초가 하는 일
- **타이틀 3줄** — "이런 웹사이트 / 만드는 `비밀` / 공개합니다". 한 단어만 파란 박스로 강조
- **노트북 목업** — 세로 영상에 가로 화면을 넣는 가장 자연스러운 방법
- **"재생" pill** — 재생 아이콘이 ⏸로 바뀐다. "지금부터 영상이 돈다"는 신호
- 2초가 지나면 노트북이 사라지고 브라우저 창이 전체폭으로 확대된다

인트로는 `statement` 로 근사하거나, 노트북 목업 씬을 하나 더 만든다.

## 6. 가져갈 것
- **보여줄 대상이 스스로 말하면 자막을 얹지 마라.** 사이트·앱에 이미 카피가 있으면 자막은 중복이고 시선만 나눈다.
- **주소창·코드 창처럼 "진짜"임을 보여주는 장치를 하나 둬라.** 말로 주장하지 않고 증거를 보여주는 쪽이 강하다.
- 세로 영상에 **가로 화면**을 넣어야 할 때는 기울어진 기기 목업 → 전체폭 확대 순서가 자연스럽다.
