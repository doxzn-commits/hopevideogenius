# 레퍼런스 분석 — "Dashboard V14" UI 킷 쇼케이스 (2026-10-30)

> 요약: 자막·사람·내레이션이 **전부 없는** 6초 루프형 제품 뷰티샷. 타이틀 + 전체폭 UI 밴드 + 코드 창 3단 구성과 페이지 사이클·카운터·마무리 스윕의 실측값. UI 킷·템플릿·포트폴리오를 "보여만 주는" 영상을 만들 때 연다.

## 결론 (먼저 읽을 것)
1. **앞의 두 레퍼런스와 목적이 다르다.** 설명하지 않고 **전시한다**. 자막 0개, 내레이션 0개, 사람 0명.
   가르치는 영상이 아니라 "이게 내가 만든 것이다"를 6초 안에 보여주는 영상이다.
2. **컷이 0회.** 6.08초 내내 한 화면이고, 바뀌는 것은 UI 밴드 안의 **페이지 내용**뿐이다.
   (레퍼런스 1 = 컷 30회, 레퍼런스 2 = 컷 1회, 이 영상 = 컷 0회)
3. **코드 창은 읽으라고 넣은 게 아니다.** 6초 내내 같은 코드가 멈춰 있다. "코드로 만들었다"는 증거물이자 장식이다.
4. 화면 교체는 **스켈레톤(회색 자리표시) → 실제 콘텐츠** 순서다. 로딩을 연출해 "진짜 앱"처럼 보이게 한다.
5. 마지막 0.5초에 **대각선 다크 스윕**이 지나가며 끝난다. 루프 이음새를 가리는 장치다.

## 1. 포맷·타이밍
| 항목 | 값 |
|---|---|
| 해상도 / fps / 길이 | 1440×2560(9:16, 2배 해상도) / 30fps / **6.08초** |
| 하드컷 | **0회** |
| 화면 교체 시점 | 1.68초 · 3.01초 · 3.41초 · 5.58초 (페이드, 컷 아님) |
| 구간 | 대시보드 0~1.68 → 메시지 1.68~3.01 → 관리 3.01~3.41 → 리워드 3.41~5.58 → 마무리 스윕 5.58~6.08 |
| 페이지당 | 1.3~2.2초. 짧은 것(0.4초)은 스치듯 지나간다 |

**관찰**: 페이지를 다 보여주려 하지 않는다. 0.4초짜리 화면도 있다 — "많다"는 인상만 남기면 되기 때문이다.

## 2. 레이아웃 (1440 기준 → 1080 환산 ×0.75)
| 요소 | 1440 | 1080 환산 |
|---|---|---|
| 타이틀 1행 "Dashboard" (흰색) | y≈716 | 537 |
| 타이틀 2행 "V14" (주황) | y≈820 | 615 |
| UI 밴드 상단 | 887 | **665** |
| UI 밴드 하단 | 1673 | **1255** (높이 590) |
| UI 밴드 좌우 | 0~1440 (**전체폭, 좌우가 잘림**) | 0~1080 |
| 코드 창 | x 156~1286 / y 1866~2356 | x 117~965 (폭 848) / y 1400~1767 (높이 367) |
| 밴드와 코드 창 사이 검정 여백 | 193 | 145 |

**UI 밴드가 화면 밖으로 잘려 나간다**는 게 핵심이다. 창 전체를 보여주지 않고 가로로 꽉 채워 **크게** 보여준다.
작게 줄여 전부 보여주면 디테일이 죽는다.

## 3. 색 (실측)
| 이름 | 값 | 쓰임 |
|---|---|---|
| 배경 | `#020002` (사실상 순수 검정) | 전체 |
| 주황 | `#F06036` 계열 | "V14" 타이틀, 리워드 카드 그라데이션, 강조 |
| 코드 창 바탕 | `#12121D` | 코드 영역 |

검정 배경 + 흰 UI + 주황 포인트. **색이 3개뿐**이라 UI 스크린샷이 그대로 주인공이 된다.

## 4. 움직이는 것 4가지 (전부)
| 모티프 | 관찰 |
|---|---|
| **페이지 사이클** | 사이드바/탭 선택이 바뀌며 화면 교체. 매번 스켈레톤 → 콘텐츠 순서 |
| **스켈레톤 로딩** | 회색 블록이 먼저 깔리고 0.2~0.4초 뒤 실제 요소가 들어찬다 |
| **숫자 카운트업** | 리워드 포인트 6,725 → 12,480 로 계속 올라감 + 진행 바가 같이 참 |
| **마무리 대각선 스윕** | 5.58초부터 어두운 사선 면이 왼쪽 위에서 지나가며 끝 (루프 이음새 가림) |

이게 전부다. 카메라 이동도, 줌도, 회전도, 파티클도 없다.

## 5. 이 형식이 통하는 이유
- **정보 밀도를 포기하고 질감을 택했다.** 읽을 것이 없으니 시선이 UI 디테일(그림자·라운드·간격)에 머문다.
- **코드 창이 신뢰를 만든다.** "디자인 시안"이 아니라 "실제로 돌아가는 것"이라는 주장을 글자 하나 없이 한다.
- **6초 = 릴스 자동 반복 2~3회.** 보는 사람이 두 번째 루프에서 디테일을 다시 본다.
- 소리가 없어도 손해가 없다. 애초에 말이 없다.

## 6. 우리 엔진으로 만들려면 (없는 것)
| 필요한 것 | 지금 상태 |
|---|---|
| `showcase` 레이아웃 — 타이틀 2행 + 전체폭 UI 밴드 + 하단 코드 창 | 없음 (`card`·`stack`·`split`뿐) |
| `code-window` 컴포넌트 — 신택스 하이라이트 + 트래픽 라이트 + 언어 라벨 | 없음 (`ui.tsx` 의 MonoLine 은 한 줄짜리) |
| **UI 스크린 사이클** — 이미지 N장을 스켈레톤→콘텐츠로 교체 | 없음. 실제 스크린샷을 쓰려면 `public/` 이미지 + `CanvasImage` 필요 |
| 스켈레톤 로딩 표현 | 부분적 — `browser-mock` 의 블록이 비슷하나 "로딩 후 교체"가 없다 |
| 숫자 카운트업 | 부분적 — `before-after` 의 `countUp` 이 있으나 독립 씬이 아니다 |
| 대각선 스윕 마무리 / 루프 이음새 처리 | 없음 |
| 자막 없는 씬 | **가능** (captions 빈 배열 허용) |
| 검정 배경 팔레트 | 없음 (`ember` 가 가장 가깝지만 글로우가 있다) |

→ 최소 구현: **`showcase` 레이아웃 + `code-window` + `screen-cycle` 씬** 셋이면 이 영상을 재현한다.
스크린샷은 `engine/public/screens/` 에 넣고 spec 에서 경로로 가리키는 방식이 맞다.

## 8. 측정 방법 (재현용)
```bash
ffprobe -v error -show_entries format=duration:stream=width,height,r_frame_rate -of compact in.mp4
ffmpeg -i in.mp4 -vf "fps=1000/300,scale=320:-1,tile=5x4" fine_%02d.jpg   # 0.3초 간격
ffmpeg -i in.mp4 -vf "select='gt(scene,0.03)',showinfo" -an -f null - 2>&1 | grep -o "pts_time:[0-9.]*"
# 밴드 경계: 세로 한 줄의 밝기 프로파일에서 밝은 구간을 찾는다
ffmpeg -ss 4 -i in.mp4 -frames:v 1 -vf "crop=2:2560:1200:0,scale=1:2560" -f rawvideo -pix_fmt gray -
```
컷이 거의 없는 영상은 `scene` 임계값을 **0.03까지 낮춰야** 교체 시점이 잡힌다(0.25로는 0건이 나온다).
